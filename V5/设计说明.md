# 设计说明

## 总体架构
- **数据采集层（Bridge）**：在流程关键节点落库，包括 Prompt 最终稿、LLM 请求/响应原文、阶段状态与耗时、任务编排与执行状态、工件内容与版本。
- **数据存储层（MySQL 8.0）**：本机部署，永久保存，不做压缩与清理。
- **管理后台服务**：独立服务提供认证与数据查询 API。
- **管理后台前端**：独立项目/端口，提供登录与数据浏览能力。

## 数据流
1. 以 `specId` 作为主键贯穿全流程。
2. Bridge 生成或接收关键事件 → 写入 MySQL。
3. 管理后台通过 API 查询 MySQL → 前端展示。

## 数据模型草案（概念级）
- **specs**：specId、创建时间、当前阶段、状态摘要。
- **stages**：specId、阶段名、开始/结束时间、耗时、状态、错误信息。
- **artifacts**：specId、artifact 类型（requirements/design/tasks）、内容、版本、更新时间。
- **prompts_final**：specId、阶段名、最终 Prompt 原文、模型信息、创建时间。
- **llm_conversations**：specId、阶段名、请求原文、响应原文、模型信息、耗时、时间戳。
- **mvp5_plans / mvp5_executions**：编排计划、依赖、执行状态、运行日志。
- **events**：关键事件与操作日志（配置变更、执行触发、失败重试等）。
- **admins / sessions**：管理员账号与登录会话。

## 登录方案
- 轻量管理员登录。
- 密码需安全存储（哈希 + salt）。
- 会话或 Token 机制用于后台访问控制。

## 运行与配置（最小自检）
- MySQL 8.0 本机部署，Bridge 启动时自动建库建表。
- 环境变量（Bridge）：
  - `PLANADB_HOST` / `PLANADB_PORT` / `PLANADB_USER` / `PLANADB_PASSWORD` / `PLANADB_NAME`
  - `PLANADB_DISABLED=1` 可临时禁用 DB 写入
- 管理员账号（首次启动自动种子）：
  - `PLANA_ADMIN_USER` / `PLANA_ADMIN_PASSWORD`（也兼容 `PLANADB_ADMIN_USER` / `PLANADB_ADMIN_PASSWORD`）
  - `PLANA_ADMIN_TOKEN_SECRET` 可选，用于固定 Token 密钥
- 启动：
  - `npm --prefix planA start`（Bridge + 主 UI）
  - 管理后台本地开发：`npm --prefix planA/admin-dashboard install` 后 `npm --prefix planA/admin-dashboard run dev`
  - 生产构建：`npm --prefix planA/admin-dashboard run build` 后访问 `http://localhost:4100/admin`
- 最小自检：
  - 访问 `http://localhost:4100/health`
  - 管理后台登录并查看 `specId` 对应的 stages / prompts / llm_conversations

## 非功能要求
- **完整性优先**：LLM 对话记录必须完整原文保存，不允许截断或压缩。
- **可追溯性**：所有表均可通过 `specId` 联动查询。
- **可读性**：字段命名与展示友好，便于管理员检索与复盘。
