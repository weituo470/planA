# V5 数据库与管理后台需求

## 目标
- 使用本地 MySQL 8.0 统一管理系统全流程数据，为复盘与迭代提供可查询的数据基础。
- 新建独立管理后台，用于数据查询与管理。
- 以 `specId` 作为全流程主键，保证跨阶段可追溯。

## 范围与不做
- 仅新增数据库与管理后台，不做历史数据迁移。
- 不提供普通用户角色，仅保留管理员（全权限）。
- 数据永久保留，不做自动清理/归档。

## 用户与权限
- 采用轻量登录方案（本地管理员账号）。
- 管理员拥有全量读写权限。

## 数据范围（“人能看懂”的信息全部入库）
- 提示词：只保存**最终 Prompt**（变量替换后的完整文本）。
- LLM 对话记录：请求与响应**原文完整保存**，不允许省略、截断或压缩。
- 流程主数据：需求、设计、任务、执行、评审等阶段的全流程记录。
- 阶段状态与耗时：开始/结束时间、耗时、状态、错误信息。
- 任务编排与执行：MVP5 编排计划、依赖关系、执行状态、运行日志。
- 产出工件：requirements/design/tasks 等文档内容与版本记录。
- 操作与事件：关键操作与系统事件（例如配置更新、执行触发、失败重试）。

## 关键一致性要求
- 完整性：LLM 全量对话记录必须原样保存，不可丢失。
- 可追溯：任何数据必须可通过 `specId` 串联回溯。
- 可读性：入库内容需可被管理员直接理解与检索。

## 管理后台需求
- 独立于现有 dashboard 的新后台（独立项目/端口）。
- 支持登录后访问，提供列表、详情、筛选与检索。
- 支持按 `specId`、时间、模型等维度查询。
- 能查看完整 Prompt 与完整 LLM 对话记录原文。

## 技术与部署约束
- 数据库：MySQL 8.0，本机安装。
- 数据永久保留，不做迁移与压缩。

## 验收标准
- 管理后台可登录并访问数据管理页面。
- 可通过 `specId` 查询并查看全流程数据。
- 任意一次 LLM 对话可完整查看原文（无缺失、无截断）。
- 最终 Prompt 可按 `specId` 与流程阶段查询。
