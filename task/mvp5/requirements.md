# MVP5：智能任务编排系统（AI依赖分析 + DAG推荐）

## 背景

当前系统已具备原子任务拆解能力，但任务之间的依赖关系仍需人工判断，存在以下痛点：
1. 无法自动识别任务间的依赖关系（文件读写、API调用、数据流等）
2. 缺少可视化执行时序图，难以理解并行执行边界
3. 需要手动分配 CLI 工具执行任务，效率低且容易出错
4. 任务失败时缺少清晰的恢复策略

## 目标

构建一个智能任务编排系统，实现：
1. **AI 自动分析依赖关系**：从任务描述、文件操作、API 调用等维度推断任务依赖
2. **可视化 DAG 拓扑**：生成任务执行时序图，清晰展示并行与串行边界
3. **智能推荐方案**：基于依赖分析和资源可用性，推荐最优执行策略
4. **灵活执行控制**：支持批准推荐方案或手动分配 CLI 执行
5. **失败隔离恢复**：任务失败只影响下游，提供一键重启

## 范围（In Scope）

### 核心功能
- AI 依赖分析引擎（文件、API、数据流、显式声明）
- DAG 可视化（React Flow 或类似库）
- 推荐方案生成器（并行度评估、CLI 分配建议）
- 执行控制面板（批准/修改/手动分配）
- 失败处理与恢复

### 依赖类型
| 类型 | 说明 | 检测方式 |
|------|------|----------|
| 文件依赖 | 任务A生成文件 → 任务B读取文件 | 解析 `runDoc` 中的文件路径 |
| API依赖 | 任务A调用API → 任务B依赖API结果 | 解析 API 调用模式 |
| 数据依赖 | 任务A写入数据库 → 任务B查询 | 解析数据操作语句 |
| 显式依赖 | `after: [taskId]` 声明 | 解析任务元数据 |
| 资源冲突 | 同时写入同一文件/目录 | 检测路径重叠 |
| CLI锁定 | 特定任务必须用特定CLI | 元数据标记 |

### 跨平台支持
- 路径规范化：Windows `\` → Linux `/`
- 环境变量处理：`%VAR%` ↔ `$VAR`
- CLI 命令适配：`.bat` ↔ `.sh`

### 失败隔离
- 失败任务显示报错信息 + 重启按钮
- 下游任务自动等待，上游已完成任务保持状态
- 支持跳过失败任务继续执行（用户确认）

## 非目标（Out Scope）

- 不做完整的分布式任务调度（单机 Bridge 即可）
- 不做复杂的资源配额管理（简单计数即可）
- 不保证全局最优并行度（以"合理并行"为准）

## 关键用户故事

1. 作为开发者，我点击「分析依赖」，系统自动生成 DAG 图，告诉我哪些任务可以并行执行。
2. 作为开发者，我看到推荐方案建议用 Codex 执行 A 任务、Claude Code 执行 B 任务，我可以一键批准或手动调整。
3. 作为开发者，当任务 A 失败时，系统显示具体错误，我修复后点击「重启」，只有 A 及其下游重新执行。
4. 作为开发者，我在 Windows 开发，系统自动处理路径差异，确保部署到 Linux 时任务正常运行。

## 验收标准（AC）

- AC1：点击「分析依赖」后，展示 DAG 图，正确标识可并行任务组
- AC2：推荐方案包含 CLI 分配建议和预计执行时间
- AC3：支持修改推荐方案后执行
- AC4：任务失败时显示错误信息，重启后不影响已完成任务
- AC5：跨平台路径处理正确（Windows 开发 → Linux 部署）
- AC6：`npm run build` 通过
