# 设计说明

## 总体架构
- Bridge 服务：负责 CLI 进程桥接、事件流、文件监听与 Diff 生成。
- Web 仪表盘：负责状态展示、任务图可视化、审批与补丁输入。
- CLI 引擎：执行真实命令，产生日志与文件变更。

## 组件关系
- Socket.io：桥接事件推送（双向）。
- node-pty：捕获 CLI 输出与输入回传。
- 文件监听：chokidar 监听 `.codex/`、`task/`、`workflow/`。

## 事件模型（摘要）
- status:update
- task:graph
- diff:preview
- approval:request / approval:resolve
- requirement:patch
- test:report
- log:append

## 数据持久化
- 事件日志：`workflow/bridge/data/events.jsonl`
- 通过事件回放恢复状态。

## 任务图与 UI
- 使用 React Flow 绘制 DAG。
- 任务拖拽后实时推送到 Bridge，触发任务图重排事件。
- Diff 与审批作为侧栏组件常驻。

## 审批与反馈
- ApprovalRequest 触发后进入 Reviewing。
- 审批通过/拒绝后回到 Thinking 或进入下一步。
- 需求补丁直接写入事件流，供 AI 消费。
