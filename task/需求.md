# AI IDE 模式需求

## 目标
- 以“规范驱动开发”为主线，让 AI 开发过程可观测、可交互、可审计。
- 通过浏览器仪表盘实现人类在环（Human-in-the-Loop）高效介入。
- 超越 Kiro 的静态规范列表，提供实时任务流监控与可视化编排。

## 核心能力
- 实时任务流监控：任务清单 → DAG 动态拓扑图，支持任务实时重排。
- 状态流转：Thinking → Executing → Reviewing，全程可见。
- Approval 打断机制：关键步骤触发审批请求，CLI 暂停，等待 Web 端确认。
- 需求补丁（Requirement Patching）：浏览器输入补丁，注入到 AI 上下文。
- 文件 Diff 侧栏：每一步执行前后实时推送 diff，不在终端滚屏。
- 对话驱动任务重构：执行失败时，Web 端对话引导 AI 更新 Task.md 并刷新 DAG。
- 测试报告弹窗：绿/红灯展示结果，支持 Submit / Retry with Feedback。

## 工作流阶段（Spec-Driven 2.0）
1. Specification：浏览器输入需求 → 生成 Requirements.md / Design.md
2. Planning：AI 拆解任务并推送任务图
3. Execution：CLI 执行，浏览器实时展示日志、diff、指标
4. Verification：测试结果弹窗与交互验收

## 技术栈与集成
- CLI Agent：OpenAI CODEX CLI
- 本地服务：Node.js + Socket.io + node-pty（桥接 CLI 输出）
- 前端：Vite + React + Tailwind + Shadcn UI
- 可视化：React Flow（任务拓扑图）
- 参考规范：OpenSpec（以工件为中心的规范驱动结构）

## 关键设计原则
- 文件系统即状态：变更与进度以文件存在/更新驱动。
- 可审计：所有事件和补丁可追溯。
- 低摩擦：AI 与人类切换成本尽量低，浏览器成为主控制台。
